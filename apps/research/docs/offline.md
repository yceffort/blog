# 리서치 오프라인 저장

목록 카드 또는 슬라이드 우클릭/롱프레스 메뉴의 **오프라인 저장**으로 덱을
선택한다. `/offline` 보관함에서 열기, 발표자 모드, 자동·수동 업데이트, 삭제를 제공한다.
앱 설치 없이도 저장할 수 있다. 링크를 방문하는 것만으로 덱을 다운로드하지 않는다.

슬라이드 주소는 `/offline/{slug}`, 발표자 화면은 `/offline/{slug}/presenter`다.
현재 장은 기존처럼 `#5` 형태의 해시로 표시한다. 저장소의 덱 식별자는 그대로라
주소 변경 때문에 기존 자료를 다시 다운로드할 필요는 없다.

저장한 자료는 온라인과 동일한 슬라이드 뷰어에서 실행된다. 전환 애니메이션
(slide/fade/zoom/glide), Mermaid, 발표자 노트, 현재·다음 슬라이드 미리보기,
타이머와 발표 화면 동기화도 오프라인에서 동작한다. 보관함에서 **슬라이드 열기**를
누른 뒤 **P** 키를 누르면 해당 슬라이드와 연결된 발표자 창이 열린다.

## 변경 감지와 자동 업데이트

사이트를 열거나 인터넷 연결이 복구되면 저장한 자료의 변경사항을 확인한다.
화면이 보이는 동안에는 5분마다 다시 확인하고, 다른 탭에서 돌아왔을 때도
마지막 확인 후 1분이 지났으면 확인한다. 사이트를 닫아 둔 동안에는 실행하지 않는다.

렌더된 슬라이드·테마·노트의 SHA-256을 ETag로 사용한다. 내용과 실행 파일 버전이
같으면 서버는 본문 없는 304 응답을 보내며 이미지·폰트를 다시 다운로드하지 않는다.
새 배포에서는 같은 주소의 이미지·폰트가 바뀐 경우까지 반영하도록 함께 갱신한다.
변경 감지 정보가 없는 기존 저장본도 첫 확인 때 자동으로 갱신한다.

다운로드가 모두 끝난 뒤 저장본을 교체한다. 이미 열린 슬라이드와 발표자 창은
자동으로 새로고침하지 않으며, 자료를 다시 열면 갱신된 저장본을 사용한다.
진행 상태와 실패 안내는 보관함에 표시하고 발표 화면에 자동 업데이트 팝업을 띄우지 않는다.
실패·취소 시 기존 자료를 유지하고, 연결 복구나 다음 확인 시 다시 시도한다.
여러 탭의 변경 확인과 저장·삭제는 Web Locks로 조율하며, 삭제한 자료를 자동으로
다시 저장하지 않는다. 수동 `업데이트` 버튼도 계속 사용할 수 있다.

## 저장 구조

- `/api/slides/[slug]/offline`: 뷰어에서 열 수 있는 덱의 렌더된 HTML, CSS, 폰트 선언,
  발표 노트. `published: false`는 기존 뷰어와 마찬가지로 목록 노출 여부만 결정하며,
  직접 주소로 연 자료는 저장할 수 있다.
- IndexedDB `research-offline`: 완료된 덱.
- localStorage `research-offline-position:*`: 마지막 읽은 장. 페이지를 바로 닫아도
  위치가 남도록 슬라이드 변경 시 동기적으로 기록한다.
- `research-deck-v1-*`: 해당 저장본의 이미지와 실제 폰트 파일. 덱 전체의 자산을
  다운로드한 뒤 IndexedDB 레코드를 교체한다. 실패/취소 시 기존 레코드는 유지한다.
- `/offline-assets/{id}/{index}`: 저장본마다 분리된 자산 주소. 온라인 페이지나
  다른 덱의 이미지 버전과 섞이지 않는다.
- `research-runtime-v1-*`: 보관함·뷰어의 HTML, JS, CSS, 폰트. 지연 로딩되는
  Mermaid 청크도 포함한다. 덱 데이터와 RSC 응답은 여기에 포함하지 않는다.
- `research-offline-meta-v1`: 검증을 마친 공통 뷰어를 가리키는 포인터.

`build` 스크립트는 Next 빌드 후 `generate-offline-runtime.mjs`를 실행한다.
생성되는 `public/offline-runtime.json`, `public/offline-shell.html`은 배포 산출물이며
Git에 넣지 않는다. **배포에서도 패키지의 `build` 스크립트를 실행해야 한다.**
각 파일의 SHA-256을 확인하므로 배포 중 이전 HTML과 새로운 JS가 섞이면 다운로드가
실패하고 기존 공통 뷰어를 유지한다. 개발 서버에서는 이 산출물이 생성되지 않으므로
오프라인 동작은 프로덕션 빌드에서 검증한다.

로컬에서 직접 사용하려면 `pnpm preview:research`를 실행하고
`http://localhost:3002`에서 자료를 저장한다. 이 명령은 빌드와 미리보기 서버 실행을
함께 처리한다. `pnpm dev:research`의 3001 포트는 개발용이며, 배포용 실행 파일을
제공하지 않으므로 저장 버튼은 미리보기 실행 안내를 표시한다.

서비스 워커는 온라인 `/offline` 및 하위 덱 경로의 문서 요청에 최신 페이지를 제공하고, 연결 실패 시
저장한 뷰어로 응답한다. 이전 뷰어만 계속 실행되어 변경 감지 코드의 업데이트가
막히지 않도록 하기 위한 처리다. 일반 페이지의
네트워크 실패는 보관함으로, `/slides/{slug}` 및 발표자 URL은 해당 저장본으로
연결한다. 보관함 링크는 Next의 RSC 캐시 없이 시작할 수 있도록 문서 탐색을 사용한다.

## 수명과 제한

첫 저장 때 공통 실행 파일도 다운로드한다. 보관함의 용량은 이 공통 파일을 제외한
덱과 자산의 용량이다. 외부 자산은 CORS를 허용해야 하며, 불투명한 응답이나 실패한
자산을 저장 완료로 표시하지 않는다. 외부 링크의 목적지나 온라인 데모는 포함하지 않는다.

다운로드 중에는 화면을 열어 두어야 한다. Web Locks로 탭 간 저장/업데이트/삭제를
직렬화한다. 브라우저가 영구 저장을 허용하지 않거나 사이트 데이터를 삭제하면
저장본이 없어질 수 있다.

업데이트된 덱의 이전 자산은 열린 오프라인 발표가 없을 때 정리한다. 공통 실행 파일의
이전 버전은 열려 있는 페이지의 지연 로딩이 깨지지 않도록 유지한다. 서비스 워커는
업데이트 때 `skipWaiting`이나 일괄 캐시 삭제를 하지 않는다.

## 검증

```sh
pnpm build:research
pnpm --filter research exec playwright install chromium
pnpm --filter research test:offline
```

테스트는 3011 포트에 프로덕션 서버를 띄우고 별도의 임시 브라우저 프로필을 사용한다.
선택한 덱만 보관되는지, 브라우저를 종료한 뒤 오프라인으로 재실행할 수 있는지,
네 가지 전환 효과의 실제 애니메이션, Mermaid, 슬라이드별 노트 본문, 타이머,
발표자 양방향 동기화·이어보기·삭제, 실패한 업데이트·취소·목록에 숨긴 덱의 저장을 확인한다.
자동 업데이트의 304 응답, 재연결·주기적 갱신, 실패 후 재시도, 기존 저장본 업그레이드,
발표 중 화면 유지도 확인한다. 데스크톱·휴대폰 세로/가로 크기에서 QR 코드 크기와
슬라이드 가장자리 링크의 클릭·터치, 기존 페이지 이동 영역의 동작을 검사한다.
경로형 주소의 직접 진입·오프라인 재시작·새로고침과 발표자 화면 연결도 검사한다.
