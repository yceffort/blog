# 리서치 오프라인 저장

저장할 덱은 목록 카드나 슬라이드의 우클릭(휴대폰은 롱프레스) 메뉴에서 **오프라인 저장**을 눌러 고른다. 저장한 덱은 `/offline` 보관함에서 열고, 발표자 모드로 띄우고, 자동 또는 수동으로 업데이트하고, 삭제할 수 있다. 앱을 설치하지 않아도 저장할 수 있고, 링크를 방문하기만 해서는 덱을 내려받지 않는다.

슬라이드 주소는 `/offline/{slug}`, 발표자 화면은 `/offline/{slug}/presenter`다. 현재 장은 이전과 같이 `#5` 형태의 해시로 표시한다. 저장소 안의 덱 식별자는 바뀌지 않았으므로 주소가 바뀌었다고 기존 자료를 다시 내려받을 필요는 없다.

저장한 자료는 온라인과 같은 슬라이드 뷰어에서 실행된다. 전환 애니메이션(slide, fade, zoom, glide), Mermaid, 발표자 노트, 현재 슬라이드와 다음 슬라이드 미리보기, 타이머, 발표 화면 동기화가 오프라인에서도 동작한다. 보관함에서 **슬라이드 열기**를 누른 뒤 **P** 키를 누르면 그 슬라이드와 연결된 발표자 창이 열린다.

## 변경 감지와 자동 업데이트

사이트를 열거나 인터넷 연결이 돌아오면 저장한 자료가 바뀌었는지 확인한다. 화면이 보이는 동안에는 5분마다 다시 확인하고, 다른 탭에 있다가 돌아왔을 때도 마지막 확인에서 1분이 지났으면 확인한다. 사이트를 닫아 둔 동안에는 확인하지 않는다.

ETag로는 렌더된 슬라이드, 테마, 노트의 SHA-256을 쓴다. 내용과 실행 파일 버전이 같으면 서버는 본문 없이 304로 응답하고, 이미지와 폰트도 다시 내려받지 않는다. 새로 배포했을 때는 주소는 같고 내용만 바뀐 이미지와 폰트까지 반영되도록 함께 갱신한다. 변경 감지 정보가 없는 예전 저장본은 첫 확인 때 자동으로 갱신한다.

저장본은 다운로드가 모두 끝난 뒤에 교체한다. 이미 열려 있는 슬라이드와 발표자 창은 자동으로 새로고침하지 않고, 자료를 다시 열었을 때 갱신된 저장본을 쓴다. 진행 상태와 실패 안내는 보관함에 표시하고, 발표 화면에는 자동 업데이트 팝업을 띄우지 않는다. 실패하거나 취소하면 기존 자료를 그대로 두고, 연결이 돌아오거나 다음 확인 때 다시 시도한다. 여러 탭에서 동시에 일어나는 변경 확인과 저장, 삭제는 Web Locks로 조율하고, 삭제한 자료를 자동으로 다시 저장하지 않는다. 수동 `업데이트` 버튼도 계속 쓸 수 있다.

## 저장 구조

- `/api/slides/[slug]/offline`: 뷰어에서 열 수 있는 덱의 렌더된 HTML, CSS, 폰트 선언, 발표 노트. `published: false`는 기존 뷰어와 마찬가지로 목록에 보일지만 정하므로, 주소로 직접 연 자료는 저장할 수 있다.
- IndexedDB `research-offline`: 저장을 마친 덱.
- localStorage `research-offline-position:*`: 마지막으로 읽은 장. 페이지를 바로 닫아도 위치가 남도록 슬라이드가 바뀔 때마다 동기적으로 기록한다.
- `research-deck-v1-*`: 저장본별 이미지와 실제 폰트 파일. 덱 전체의 자산을 내려받은 뒤에 IndexedDB 레코드를 교체하고, 실패하거나 취소하면 기존 레코드를 유지한다.
- `/offline-assets/{id}/{index}`: 저장본마다 따로 둔 자산 주소. 온라인 페이지나 다른 덱의 이미지 버전과 섞이지 않는다.
- `research-runtime-v1-*`: 보관함과 뷰어의 HTML, JS, CSS, 폰트. 지연 로딩되는 Mermaid 청크도 들어 있고, 덱 데이터와 RSC 응답은 넣지 않는다.
- `research-offline-meta-v1`: 검증을 마친 공통 뷰어를 가리키는 포인터.

`build` 스크립트는 Next 빌드가 끝나면 `generate-offline-runtime.mjs`를 실행한다. 이때 생기는 `public/offline-runtime.json`과 `public/offline-shell.html`은 배포 산출물이라 Git에 넣지 않는다. **배포할 때도 패키지의 `build` 스크립트를 실행해야 한다.** 파일마다 SHA-256을 확인하므로, 배포 도중 이전 HTML과 새 JS가 섞이면 다운로드가 실패하고 기존 공통 뷰어를 그대로 쓴다. 개발 서버에서는 이 산출물이 만들어지지 않으니 오프라인 동작은 프로덕션 빌드에서 확인한다.

로컬에서 직접 써 보려면 `pnpm preview:research`를 실행하고 `http://localhost:3002`에서 자료를 저장한다. 이 명령 하나로 빌드와 미리보기 서버 실행이 함께 끝난다. `pnpm dev:research`의 3001 포트는 개발용이라 배포용 실행 파일이 없고, 저장 버튼을 누르면 미리보기로 실행하라는 안내가 뜬다.

서비스 워커는 온라인 상태에서 `/offline`과 그 아래 덱 경로의 문서를 요청하면 최신 페이지로 응답하고, 연결에 실패하면 저장한 뷰어로 응답한다. 이전 뷰어만 계속 실행되면 변경 감지 코드가 업데이트되지 못하기 때문이다. 일반 페이지에서 네트워크가 실패하면 보관함으로, `/slides/{slug}`와 발표자 URL은 해당 저장본으로 연결한다. 보관함의 링크는 Next의 RSC 캐시 없이도 열리도록 문서 탐색으로 이동한다.

## 수명과 제한

처음 저장할 때 공통 실행 파일도 함께 내려받는다. 보관함에 표시하는 용량은 이 공통 파일을 뺀 덱과 자산의 용량이다. 외부 자산은 CORS를 허용해야 하고, 불투명한 응답이나 받지 못한 자산이 있으면 저장 완료로 표시하지 않는다. 외부 링크가 가리키는 페이지나 온라인 데모는 저장하지 않는다.

다운로드하는 동안에는 화면을 열어 두어야 한다. 탭 사이의 저장, 업데이트, 삭제는 Web Locks로 한 번에 하나씩 처리한다. 브라우저가 영구 저장을 허용하지 않거나 사이트 데이터가 지워지면 저장본도 없어질 수 있다.

업데이트된 덱의 이전 자산은 열려 있는 오프라인 발표가 없을 때 정리한다. 공통 실행 파일의 이전 버전은 이미 열린 페이지의 지연 로딩이 깨지지 않도록 남겨 둔다. 서비스 워커는 업데이트할 때 `skipWaiting`을 호출하거나 캐시를 한꺼번에 지우지 않는다.

## 검증

```sh
pnpm build:research
pnpm --filter research exec playwright install chromium
pnpm --filter research test:offline
```

테스트는 3011 포트에 프로덕션 서버를 띄우고, 따로 만든 임시 브라우저 프로필을 쓴다. 확인하는 항목은 다음과 같다.

- 저장과 실행: 고른 덱만 보관되는지, 브라우저를 종료한 뒤 오프라인으로 다시 실행할 수 있는지.
- 뷰어: 네 가지 전환 효과의 실제 애니메이션, Mermaid, 슬라이드별 노트 본문, 타이머.
- 발표자 화면: 양방향 동기화, 이어보기, 삭제.
- 실패 처리: 실패한 업데이트, 취소, 목록에 숨긴 덱의 저장.
- 자동 업데이트: 304 응답, 재연결과 주기적 갱신, 실패 후 재시도, 예전 저장본 업그레이드, 발표 중 화면 유지.
- 화면 크기: 데스크톱과 휴대폰 세로, 가로에서 QR 코드 크기, 슬라이드 가장자리 링크의 클릭과 터치, 기존 페이지 이동 영역의 동작.
- 경로형 주소: 직접 진입, 오프라인 재시작, 새로고침, 발표자 화면 연결.
