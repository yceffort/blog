## 오늘 하나만 본다면

### 에이전트 메모리 형식이 제각각인 지금은 2019년 이전의 관측 도구 시장과 같습니다

`lorekit.io` (Hacker News 경유) [원문](https://www.lorekit.io/blog/open-agent-memory-format)

내 컴퓨터에는 AI 도구가 "기억"을 저장하는 형식이 이미 네 가지 있고, 서로 읽지 못합니다.

- 전형적인 개발 환경에는 AGENTS.md나 CLAUDE.md(저장소마다 두는 에이전트용 지침 파일), `.cursor/rules/*.mdc`, Anthropic 메모리 도구가 `/memories` 디렉터리에 쓰는 파일, Copilot이 GitHub 쪽에 저장하는 저장소별 사실, JSONL 지식 그래프를 쓰는 memory MCP 서버가 섞여 있습니다. CI 에이전트가 배운 교훈은 그것을 쓴 도구 안에 갇히고, 에디터 에이전트나 다음에 쓸 도구는 읽지 못합니다.
- 저자는 2019년 이전 관측(observability) 시장과 같은 상태라고 봅니다. 당시에는 벤더마다 자체 에이전트와 계측 라이브러리, 데이터 형식이 있었고, 경쟁하던 OpenTracing과 OpenCensus가 합쳐져 OpenTelemetry가 되면서 데이터 모델, 시맨틱 컨벤션(`service.name` 같은 공용 이름), 프로토콜(OTLP), 참조 구현 네 층에 합의했습니다. 벤더는 저장, 질의, 분석에서 계속 경쟁합니다.
- 기존 형식을 표로 비교하면 모두 같은 네 질문에 다르게 답합니다. 기억이 어디서 참인지, 정체성이 무엇인지(두 번째 쓰기가 갱신인지 중복인지), 내용이 무엇인지, 언제 참이 아니게 되는지입니다. 유일한 진짜 갈림길은 누가 쓰느냐입니다. 지침 파일은 사람, 메모리 도구와 Letta는 모델, Mem0와 Graphiti는 대화에서 사실을 뽑는 서비스가 씁니다. 저자는 스펙이 고르지 말고 기록만 하자고 합니다.
- 제안하는 구조는 마크다운 본문에 frontmatter 봉투를 붙인 레코드입니다. address, key, id, lifecycle, written_by, attributes 필드를 두고, OpenTelemetry처럼 컨벤션 레지스트리, MCP로 노출하는 write, read, list, search, archive 계약, 참조 구현 대신 적합성 테스트를 두자고 합니다. 저장, 랭킹, 임베딩은 스펙 밖에 둡니다. 기존 제안(MacPaw의 Portable Memory, Open Memory Protocol, Cognee의 COGX)은 벤더 간 내보내기에 치중해 있고, CI 잡, 에디터 에이전트, 리뷰 봇이 한 저장소의 같은 자리를 동시에 읽고 쓰는 "라이브 주소 지정"은 비어 있다고 지적합니다.
- 저자는 반론도 직접 적습니다. 메모리를 만드는 사람의 글이라는 점, MCP가 이미 표준이라는 주장(MCP는 호출을 표준화할 뿐 레코드는 아닙니다), 공유 메모리가 프롬프트 인젝션 통로가 된다는 점, xkcd 927 문제입니다. 인젝션은 작성자 기록과 서명, 레코드가 의존하는 코드를 가리키게 하는 방식으로 줄일 수 있지만 막지는 못한다고 인정합니다. 기본값을 망각으로 할지 같은 열린 질문도 남겨 둡니다.

OpenTelemetry를 직접 다뤄 본 독자에게는 "합의할 층과 경쟁할 층을 가르는" 틀이 익숙하게 읽힙니다. 에이전트 지침 파일을 팀 공통 자산으로 관리하는 일의 다음 단계가 무엇인지도 보여 줍니다. 다만 저자가 LoreKit이라는 메모리 도구를 만드는 사람이고, 필드 이름은 제안이 아니라 예시라고 스스로 밝힌 초안 수준의 글입니다.

### 에이전트 터미널 탭이 스무 개가 되면, 큐를 git에 두고 한 번에 하나만 닫으라고 합니다

`sergeykuhne.com` (Hacker News 경유) [원문](https://sergeykuhne.com/blog/fighting-ai-brain-fry)

Claude Code를 쓰다 보면 탭 20개에 흩어진 맥락을 머릿속에 들고 있다가 어느 순간 무너집니다.

- 저자는 문제를 순서(sequencing)와 맥락(context) 둘로 진단합니다. 에이전트의 응답을 기다리는 사이 다른 작업을 열고, 첫 작업의 응답이 오면 확인 질문과 후속 질문, 곁가지 작업이 각자 탭을 요구하면서 스레드가 늘어난다는 설명입니다. 휴식을 취하라거나 범위를 줄이라는 흔한 조언 대신 우선순위 큐로 일을 조직했습니다.
- 큐는 git에 있습니다. 티켓은 코드 옆에 둔 마크다운 파일이고 보드 상태는 커밋된 스냅샷이라, 채팅 창이나 머릿속에는 중요한 것이 남지 않고 세션이 죽어도 큐는 남습니다. 에이전트는 주기마다 보드를 돌며 새 티켓을 조사하고, 사람이 안전하다고 태그한 티켓을 만들고, 테스트와 브라우저 확인을 돌리고, 배포된 것을 검증합니다. 민감한 코드는 브랜치에서 만들며 먼저 묻고, 프로덕션 배포는 하지 않습니다.
- 에이전트가 하지 못하는 것은 결정입니다. 그래서 사람의 판단이 필요한 항목(변경 리뷰, 질문 답변, 트레이드오프 판정)은 스크립트가 보드 전체를 읽어 "오너 인박스"라는 한 곳에 우선순위 목록으로 모읍니다. 읽는 화면은 매 주기마다 git에서 다시 만드는 Claude 아티팩트 한 페이지이고, 판정은 카드에 달려 git으로 돌아갑니다. 페이지는 뷰어일 뿐 기록은 git입니다.
- 핵심은 "닫기"입니다. 항목 하나를 골라 맥락을 올리고, 결정하거나 행동을 요청한 뒤 큐에 되돌려 놓으면 맥락도 함께 닫혀서 다음 항목에 집중할 수 있다고 합니다. 여전히 피곤하지만 산만하거나 길을 잃은 느낌은 없다고 합니다. 남은 과제는 티켓 하나를 20분이 아니라 1분에 올릴 만큼 맥락을 소화 가능하게 내놓는 일과, 사람의 판정을 기다리다 막혀 무한 루프를 도는 티켓을 막는 일입니다.

에이전트를 병렬로 돌릴수록 병목이 사람의 판단과 검증으로 옮겨 간다는 점을 구체적인 운영 방식으로 보여 줍니다. AI 시대의 리뷰 체계를 고민하는 독자에게 참고가 됩니다. 다만 한 사람의 자기 보고이고, 생산성이 얼마나 올랐는지에 대한 수치는 없습니다.

### Claude Code 연 244회 릴리스 중 4분의 3이 시스템 프롬프트를 바꿨다는 이유로 떠났습니다

`caleb.software` (Hacker News 경유) [원문](https://caleb.software/posts/claude-to-pi.html)

올해 Claude Code는 244번 릴리스됐고, 그중 3/4 이상이 시스템 프롬프트나 도구 설명을 바꿨습니다. 2026년 9월 21일에 쓴 글입니다.

- 저자는 1년 넘게 Claude Code를 써 온 사용자로, 작은 불만이 쌓여 주력 코딩 하네스(모델을 감싸 도구를 쥐여 주는 실행 틀)를 오픈소스 Pi로 옮겼습니다. 계기는 AGENTS.md입니다. CLAUDE.md와 AGENTS.md 두 형식 사이를 복사하거나 심볼릭 링크로 이어야 하는 불편이었는데, 결정 하루 뒤 Anthropic이 AGENTS.md 지원을 발표했지만 "너무 늦었다"고 합니다.
- 불만의 하나는 IDE 연동입니다. VSCode에서 파일의 선택 영역을 컨텍스트로 넘기는 기능은 한 번에 세션 하나만 연결할 수 있어서, 탭을 하나 더 열면 선택 이벤트를 받지 못합니다. 2025년 12월부터 보고된 이슈가 전혀 다른 버그의 중복으로 닫혔다고 합니다. 공식 GUI 확장은 여러 탭을 지원하지만 슬래시 명령 절반이 동작하지 않고, 커스텀 상태줄이 없고, 서브에이전트 출력이 시간순으로 메인 스레드에 섞여 읽기 어렵다고 합니다.
- 더 큰 문제로 꼽는 것은 안정성입니다. 릴리스 대부분이 프롬프트와 도구 설명을 바꾸는데, 이는 새 지시가 사용자 프롬프트나 저장소 관례와 충돌할 때 LLM의 동작을 크게 바꿀 수 있다는 설명입니다. 시스템 프롬프트를 80% 줄이고도 Pi보다 오버헤드가 크며, Bash 도구 설명만 약 3,000토큰인데 대부분 git과 GitHub PR 사용법입니다. 모델이 이미 아는 내용이고, 일일 사용자 100만 명에 하루 요청 1억 건을 가정하면 1,000토큰만 줄여도 연간 수백만 달러를 아낄 수 있다는 계산입니다(저자의 가정입니다).
- 저자는 이 글이 불평이라는 점을 인정하고, 하네스는 새로운 분야라 선구자가 어려웠음을 인정합니다. 결론은 Claude Code가 뚜렷한 비전 없이 기능을 쌓는 제품 같고, 요청에 "아니오"라고 말할 사람이 없는 듯하다는 것입니다. Pi로 옮긴 뒤 여러 탭 처리 확장을 20분 만에 직접 작성했다고 합니다.

AI 코딩 도구를 팀 표준으로 정할 때 고려할 변수인 "도구 변경이 내 설정과 동작을 얼마나 흔드는가"를 수치로 보여 줍니다. 다만 개인 사용자의 불만 글이고, 프롬프트 변경이 품질에 미친 영향을 측정한 것은 아닙니다. 토큰 절감액도 가정에 기반한 추정입니다.

### Goldman이 트레이더와 은행가에게서 코딩 에이전트를 회수한 이유는 리뷰 없이 도는 코드입니다

`thestateofai.com` (Hacker News 경유) [원문](https://www.thestateofai.com/news/goldman-sachs-claude-code-traders-bankers)

7월에 CIO가 비개발자의 "바이브 코딩"을 칭찬하던 Goldman이 10월에는 그 도구를 엔지니어 외에게서 거둬들였습니다.

- Bloomberg 보도를 정리한 기사에 따르면, 10월에 갱신된 내부 지침이 Claude Code와 GitHub의 AI 도구 사용을 약 12,000명의 엔지니어(전체 직원 약 47,000명 중)로 제한했습니다. 고객 거래 흐름을 모니터링하고 시장과 포지션을 모델링하던 트레이더들이 불만이라고 합니다. 트레이딩, 퀀트 리서치, 소프트웨어 엔지니어링을 아우르는 strats는 계속 접근할 수 있고, 여러 회사 모델을 쓰는 사내 AI 어시스턴트는 전사에 남아 있습니다. 제한 대상은 스스로 코드를 쓰고 실행하는 외부 에이전트입니다.
- 4월의 홍콩 제한은 위치와 계약 조건에 근거한 것이었고, 이번은 역할에 근거한 제한이라는 점이 다릅니다. 기사가 짚는 위험은 세 가지입니다. 에이전트는 사용자와 같은 권한으로 파일을 읽고 코드를 쓰고 실행하는데, 엔지니어의 코드는 리뷰, 테스트, 배포 통제를 거치지만 트레이더가 만든 스크립트는 그 없이 매일 쓰일 수 있습니다. 은행은 거래 부서와 딜 부서 사이 정보 장벽을 유지해야 하는데 에이전트가 만든 도구는 그 통제를 염두에 두지 않았습니다. 그리고 코드를 이해하는 사람이 없을 수 있습니다.
- 비용도 한 요인일 수 있다고 합니다. 에이전트는 토큰 단위로 과금되고, 전 직원에게 풀었던 몇몇 회사는 지출이 늘었습니다. Amazon은 에이전트로 의미 없는 작업을 돌려 순위를 올리는 직원이 나오자 내부 리더보드를 닫았고, Accenture는 직원당 월 29달러의 Claude를 지원합니다. 반대로 Barclays는 연말까지 개발자의 절반이 Claude Code를 쓰길 기대하고, 3주 뒤 5,000명 감원에 개발자도 포함했다고 합니다.
- 매체의 입장은 "제한은 옳았지만 방식이 틀렸다"입니다. 에이전트가 쓴 코드는 읽을 수 있는 사람이 리뷰해야 하는 것이 맞지만, 지침 갱신만으로 회수하면 좋은 용도를 찾은 트레이더를 위험 요인으로 취급하는 셈이라는 것입니다. 제안은 에이전트가 만든 도구가 프로덕션 데이터에 닿기 전에 책임질 엔지니어를 지정하고, 기존의 정보 장벽과 데이터 권한, 소프트웨어 승인 규칙을 에이전트 코드에도 적용하고, 도구를 회수할 때 무엇에 쓰였는지 기록하라는 것입니다.

"누가 에이전트가 만든 코드의 주인인가"라는 검증 체계 문제를 규제 산업의 실제 사례로 보여 줍니다. 팀에 에이전트를 확산할 때 어떤 선을 그을지 생각해 보기 좋습니다. 다만 Bloomberg 보도의 2차 요약이고, 매체 의견이 섞여 있으며, Goldman 쪽의 공식 설명은 짧은 발언뿐입니다. 비용이 이유였다는 대목도 추정입니다.

### 개발자가 실수로 커밋한 printf 로그 88만 건이 "어디서 코드를 이해하기 어려워하는가"를 보여 줍니다

`link.springer.com` (Lobsters 경유) [원문](https://link.springer.com/article/10.1007/s10664-026-10988-z)

printf 디버깅은 가장 흔한 이해 전략인데도, 지워지는 로그라서 연구된 적이 거의 없었습니다.

- 연구진이 노린 지점은 개발자가 임시 로그를 실수로 커밋했다가 "remove console.log", "delete print" 같은 메시지로 지우는 수정 커밋입니다. 이 커밋이 보통은 로컬에서만 존재하던 임시 로그의 흔적을 남깁니다. GitHub Archive와 BigQuery에서 Java, JavaScript, Python 커밋을 모아 제거된 로그 882,438건의 데이터셋을 공개했습니다. 임시 로그는 대개 log4j 같은 프레임워크가 아니라 `System.out.println` 같은 가벼운 출력 함수로 쓴다는 점이 탐지를 쉽게 합니다.
- 이 데이터에는 한계가 있어 개발자 라이브 스트림 36시간 분량의 질적 분석을 덧붙였습니다. 커밋 데이터는 실수로 남은 로그만 보여 주지만, 라이브 스트림은 임시 로그를 쓰는 모든 순간을 보여 주기 때문에 상황과 동기를 이해하는 데 쓰였습니다.
- 발견 하나는 로그가 코드의 특정 위치에 쏠린다는 것입니다. JavaScript에서는 전체 함수 분포에서 기대되는 것보다 비동기 함수와 콜백에 print를 더 많이 넣었고, Java에서는 스레드 관련 클래스에 더 많이 넣었습니다. 세 언어 모두에서 순환 복잡도가 높은 함수에 임시 로그가 더 자주 쓰였습니다.
- 개발자들은 콘솔 출력을 프로그램 상태나 실행 흐름을 빠르게 식별하고 비교할 수 있게 구조화하기도 했습니다. 연구진은 이를 프로그램 이해에 쓰이는 "빵 부스러기"로 보고, 복잡도 같은 구조 지표나 소규모 참가자 실험의 대안으로 실제 행동 데이터를 쓸 수 있다고 주장합니다. 수집된 본문은 서론과 배경 절까지여서 결과의 정량 수치(비율 등)는 확인하지 못했습니다.

개발자가 코드를 이해하는 시간이 전체의 35~58%라는 인용과, AI가 만든 코드를 감사하고 이해하는 일이 가장 어려운 부분이라는 인용이 배경으로 깔려 있어 리뷰 체계를 고민하는 독자에게 맞닿습니다. 다만 본문이 잘려 있어 결론의 강도를 확인하지 못했고, 연관성을 보여 줄 뿐 인과를 증명하지는 않습니다.

### 브라우저가 이미 강력한 애플리케이션 플랫폼이고, 그 접근 비용이 매일 떨어지고 있다고 합니다

`ftrain.com` (Paul Ford, Hacker News 경유) [원문](https://ftrain.com/aboard-the-web-is-more-than-enough)

URL에 데이터를 저장하는 웹 오피스 제품을 낸 작가이자 개발자가, 호스팅비는 0원이었는데 수십만 명이 몰렸다고 씁니다.

- 저자는 tinylittleoffice.com을 출시했고, 트래픽이 몰려 Cloudflare 무료 플랜 한도를 넘겨 결제 정보를 넣은 뒤에도 호스팅 비용은 0원이었다고 합니다. 오피스 스위트 제작에 든 노력은 긴 뉴스레터 글 하나를 쓰는 노력의 두 배쯤이었다고 합니다. 이 제품은 21개 언어로 냈습니다.
- 주장은 브라우저가 20년 전부터 강력했지만 이제는 그 힘에 접근하는 비용이 계속 떨어진다는 것입니다. Web Crypto, WebAssembly, WebGL, Web Audio, PDF.js가 예로 나옵니다. 저자는 이것들을 알고 있었지만 제대로 들여다본 적이 없었고, 오픈소스 코드를 받아 쓰기에 급급했다고 합니다.
- 사례는 Simon Willison이 만든 3D 브라우저 게임 Battle Drones입니다. 멀티플레이이고 오프라인에서도 동작하며 GitHub에 호스팅했습니다. 저자의 설명으로는 이 API들이 개인이 아니라 Google 같은 대형 팀을 위해 설계돼 복잡했고, 한 가지를 익히면 나머지를 익힐 시간이 없었습니다. 이제 3D와 소리가 있는 게임이 비행기 안에서도 동작합니다.
- 함의로 앱스토어 경제가 흔들린다고 봅니다. 앱스토어에 내는 높은 비용이 정당화되기 어려워지고, 몇 주 안에 웹 서버에서 0원으로 아이디어를 시험할 수 있다는 것입니다. 소프트웨어 개발이 점점 글쓰기와 비슷해지는데, 글쓰기는 대가를 받기 어려운 일이라 소프트웨어 개발자가 처음으로 가치 절하를 겪는 점이 씁쓸하다고 합니다.

웹 플랫폼 API 전반을 AI가 접근 가능하게 만든다는 논지는 웹 성능과 브라우저 쪽에서 일하는 독자에게 낯설지 않고, 개인이 어디까지 만들 수 있는지에 대한 감각을 줍니다. 다만 근거는 저자 본인의 출시 경험과 한두 사례이고, 이 글은 기술 분석이 아니라 에세이입니다. "AI 버블"이나 개발자 가치 하락에 대한 전망은 근거 없이 던진 의견입니다.
