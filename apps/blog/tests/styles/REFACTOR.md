# 스타일 리팩토링 검증

비교 기준은 작업 시작 시 보존한 **미커밋 Full StyleX 작업 트리**다. Tailwind를 사용하던 HEAD와 비교한 이전 마이그레이션 보고서와 구분한다. 기준 소스와 빌드는 `/Users/yceffort/private/.blog-style-refactor-baseline/apps/blog`에 보존했다.

## 변경

- 컴포넌트 StyleX의 반복 레이어를 묶고, 직접 부착되는 스타일에서 불필요한 클래스 조건을 제거했다.
- 문서 테마·전환 효과·Markdown 타이포그래피 등 문맥 선택자는 소유 영역의 CSS로 옮겼다. 본문에 클래스를 주입하던 rehype 변환기를 제거했다.
- MDX 래퍼의 중복 클래스 연결을 정리했다. 접근성 스타일은 About에서 분리했고, 시리즈 행과 설명문은 명시적인 전용 스타일을 사용한다.
- 사용자 설정은 마지막 `preferences` 레이어에 둬 미니멀 모드가 컴포넌트 애니메이션을 끌 수 있게 했다.
- 기존 색상 변환과 정확히 같은 화면을 유지하기 위해 프로덕션 최적화의 호환 처리는 유지했다. 1회와 2회 변환의 결과가 달랐다.

## 검증

- 프로덕션 빌드, TypeScript, 전체 린트, 스타일 린트, 변경 파일 포매팅 검사 통과. 전체 린트에는 기존 경고가 남아 있다.
- 유틸리티 스타일 **26,880개 비교**와 코드 블록 타이포그래피 회귀 검사 **12개 조건** 통과.
- 13개 경로의 모바일/데스크톱·라이트/다크, 메뉴/검색/설정, 팔레트 5종, 필름 그레인, 미니멀 모드까지 **90개 조건에서 계산 스타일·가상 요소·내용·위치·픽셀 차이 0**.
- 정상 모션과 미니멀 모드를 포함한 **16개 조건에서 CSS 애니메이션 설정과 키프레임 일치**.

정지 화면은 기존 비교 방식대로 모션을 고정하고 WebGL 캔버스 픽셀을 마스킹한다. JavaScript/WebGL 애니메이션 프레임까지 동일하다는 의미는 아니다. 비교 허용 오차를 추가하지 않았다. 팔레트 전환 직후 계산 스타일에서 간헐적으로 오래된 자동 여백이 읽히는 문제는, 요소 위치를 먼저 읽어 레이아웃 계산을 완료한 뒤 스타일을 수집하도록 수정했다.

## 크기

아래는 변경 전후의 프로덕션 빌드 파일과 두 서버의 HTTP 응답 크기다. CSS gzip은 주 스타일시트 파일을 gzip으로 압축한 값이며, HTML gzip은 실제 응답 본문의 인코딩된 바이트 수다. FCP·LCP나 실사용자 성능을 새로 측정한 결과는 아니다.

| 항목                    |      이전 |      이후 |    변화 |
| ----------------------- | --------: | --------: | ------: |
| StyleX 정의 + CSS 줄 수 | 27,606 줄 | 11,513 줄 | -58.30% |
| 주 CSS (압축 전)        | 411,618 B | 229,057 B | -44.35% |
| 주 CSS (gzip)           |  61,240 B |  36,578 B | -40.27% |
| 표본 글 HTML (gzip)     | 102,689 B |  63,859 B | -37.81% |

표본 글은 `/2026/08/k8s-for-frontend-1`이다. 해당 HTML의 클래스 속성은 251,678→34,036 bytes로 줄었다. 중복 클래스 토큰은 2,087→24개로 줄었고, 남은 중복은 썸네일 없는 글 행의 공통/변형 클래스다.
