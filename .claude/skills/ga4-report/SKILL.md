# GA4 성과 리포트

GA4 Data API에서 실측 데이터를 뽑아 성과 분석 아티팩트를 만들고, **기존 아티팩트 URL을 업데이트**한다. 새 아티팩트를 만들지 않는다.

- 아티팩트 URL: `https://claude.ai/code/artifact/8a232bc5-0bb9-439b-868e-91e0eead2066`
- favicon: `📈` (변경 금지) · 제목: `yceffort 성과 리포트` (유지)
- 이 세션이 해당 아티팩트를 발행한 적이 없으면 Artifact 호출에 `url` 파라미터로 위 주소를 넘겨 업데이트한다.

## 절차

### 1. 데이터 조회

```bash
node .claude/skills/ga4-report/scripts/fetch-ga4.cjs --out <스크래치패드>/ga4-data.json
```

- 기본: 비교 기간 28일(`--days`), 트렌드 91일(`--trend`). 사용자가 기간을 지정하면 조정한다(예: 월간 확정 리포트는 전월 1일~말일 개념으로 `--days`를 맞춘다).
- 자격증명은 `apps/blog/.env.local`에서 자동 로드된다. 없으면 실행 환경이 로컬이 아닌 것이므로, `vercel env pull`을 시도하거나 사용자에게 로컬 실행을 안내한다.
- 결과 JSON: `daily`(일별 사용자·세션·PV), `totalsCompare`(현재 vs 직전 기간), `topPosts`(PV·사용자·체류합), `channels`, `sources`, `countries`, `devices`, `newReturning`, `recentPosts`(최근 2개월 발행 경로).
- 레퍼러·흐름용: `referrals`(source/medium), `referrerUrls`(레퍼러 URL 원본), `channelLanding`·`sourceLanding`(유입 × 랜딩 페이지 교차), `landingDepth`(랜딩별 세션·참여·PV·이탈률).

### 2. 발행일 대조

스파이크를 귀속시키기 위해 대상 기간 포스트의 frontmatter를 확인한다:

```bash
grep -H "^date:" apps/blog/posts/{연도}/{월}/*.md | grep -v '\.en\.md'
```

제목도 같은 파일의 `title:`에서 가져온다(차트 라벨은 한국어 실제 제목 사용, 길면 자연스럽게 축약).

### 3. 분석 규칙 (데이터 함정)

- **`totalsCompare` 행 순서를 절대 가정하지 말 것**: GA4가 `previous` 행을 먼저 반환하는 경우가 있다. 반드시 `r.d[0]`의 dateRange 이름(`current`/`previous`)으로 골라 쓴다. 검증법: `screenPageViews`는 합산 지표라 `daily`의 해당 구간 합과 정확히 일치해야 한다. 어긋나면 행이 뒤집힌 것이다.
- **로컬 dev 트래픽 혼입**: `referrerUrls`에 `http://localhost:3000`·`3001`이 잡힌다. 운영 GA4에 개발 중 조회가 그대로 들어오고 있다는 뜻이므로, 레퍼러 표에서 분리해 표기하고 총량을 각주에 남긴다. 미발행(`published: false`) 초안 경로의 조회수도 대부분 이 트래픽이다.
- **레퍼러 3분류**: `referrerUrls`는 외부 / 내부 이동(`https://yceffort.kr/...`) / 로컬 dev로 나눠서 읽는다. 내부 이동 합계는 "글에서 글로 넘어간 양"의 대리 지표로 쓸 수 있다.
- **채널 리포트가 리퍼럴을 과소 집계함**: 서피트는 링크에 `?ref=surfit.io`를 붙여 보내는데, 레퍼러 헤더가 없는 유입이 많아 상당수가 Direct로 분류된다. `sourceLanding`에서 이 쿼리스트링을 지문 삼아 채널 무관하게 합산한 **보정치**를 함께 제시한다(2026-08 기준 채널 229세션 대 보정 400세션).
- **크롤러 판별**: 사용자≈세션≈PV가 1:1:1이면 크롤러로 추정한다. 상시 사례: 싱가포르(국가별에서 ⚠ 표기). 일별 스파이크도 같은 비율이면 "크롤러 버스트 추정"으로 주석한다(예: 2026-07-01의 1,251명). 실사용자 수는 크롤러 제외 추정치를 함께 적는다.
- **계측 단절**: 2026-08-10에 SPA page_view 계측이 시작되어 그 전후의 **페이지뷰·참여율·평균 세션 시간은 직접 비교 불가**. 비교 기간이 8/10을 걸치면 KPI에 ⚠ 배지를 달고 사용자·세션 기준으로만 해석한다. 양쪽 기간이 모두 8/10 이후면 이 주의사항은 불필요하다.
- **집계 중인 오늘**: 마지막 날짜는 "(집계 중)"으로 표기한다.
- **존재하지 않는 경로** (`/2026/08/this-post-does-not-exist` 등) 유입은 본문 표에서 제외하고 각주로만 언급한다(LLM·크롤러 추측 링크 추정).
- 파생 지표: 글별 평균 체류 = `userEngagementDuration / activeUsers` (초 → "N분 NN초").

### 4. 리포트 작성

`template.html`(이 스킬 디렉토리)을 스크래치패드로 복사한 뒤 데이터와 카피를 교체한다. 디자인 토큰·차트 코드는 유지하고, 다음만 갱신한다:

1. **헤드라인**: 그 기간의 가장 큰 발견 한 문장 (매번 변주)
2. **KPI 4타일**: 사용자·세션·PV·참여율 + 직전 기간 대비 (계측 영향 지표는 ⚠)
3. **요약 3줄** (lede)
4. **일별 트렌드**: `DAILY` 상수(날짜·사용자·PV), `EVENTS` 상수(발행일·이상 이벤트). 날짜를 하루씩 밀리지 않게 원본 JSON과 대조 검증할 것
5. **인기 글 TOP 10** (`TOP_POSTS`): 2025년 이전 글에는 에버그린 배지
6. **유입 경로** (`CHANNELS` + 외부 레퍼러 리스트 + 레퍼러 URL 원본 표 + 리퍼럴 보정 콜아웃)
7. **어디서 어느 글로 오는가**: `sourceLanding`을 mermaid `flowchart LR`로. 소스 노드 5개 안팎, 랜딩 글 7개 안팎으로 줄이고 간선 라벨에 세션 수를 적는다. 굵은 간선(`==>`)은 상위 유입에만 쓴다
8. **사용자 흐름**: `landingDepth`를 랜딩 유형(글 상세 / 홈 / 목록 / `(not set)`)으로 묶어 mermaid `flowchart TD`로. 참여·이탈·PV per 세션까지 잇고, 상위 40개만 집계된다는 사실을 각주에 밝힌다
9. **독자** (`COUNTRIES`·기기·신규/재방문)
10. **신규 글 성과 표** (`RECENT`): 발행일 순, 시리즈 태그. `published: false`인 초안은 제외하고 각주로만 언급한다
11. **인사이트 카드**: 데이터에서 도출한 발견 3~5개
12. **다음 글, 다음 방향**: 루트 `CLAUDE.md`의 "블로그 포스트 전략" 및 메모리의 보류 글감과 연결해 다음 글 방향을 제안

mermaid는 아티팩트가 기본 렌더링하므로 `<pre class="mermaid">`로 넣기만 하면 된다. 외부 라이브러리를 로드하지 말 것. `sankey-beta`처럼 최신 문법은 피하고 `flowchart`만 쓴다.

**하드코딩된 값 확인**: `barList` 호출의 `max:` 3곳과 신규 글 표의 `(r.pv / N)`은 상수 배열과 별도로 박혀 있다. 데이터를 바꾸면 이 4개도 새 최댓값으로 함께 고쳐야 막대 길이가 맞는다.

작성 후 브라우저(chrome-devtools MCP)로 라이트/다크/모바일 렌더링을 확인하고 게시한다. 게시 label에는 기간을 적는다(예: `2026-08`). 게시 전 `action: "list"`나 WebFetch로 현재 게시본을 확인해야 다른 세션의 최신본을 덮어쓰지 않는다.
